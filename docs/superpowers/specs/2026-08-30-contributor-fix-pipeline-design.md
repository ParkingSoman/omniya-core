# Contributor fix pipeline — design

Date: 2026-08-30
Branch: `testing`
Status: approved design, not built

## The problem

A blind alpha contributor finds a bug. They write a good description and attach a
diagnostics dump from `Help → Copy braille input diagnostics`. They email it to
Shonu. Shonu pastes it into Claude Code. Claude Code fixes it and pushes.

Every step of that loop except the first and the last is Shonu acting as a
courier. The reports are already good. The diagnostics are already complete. The
fix is already automatic. Only the hand-off is manual.

This design removes the hand-off.

## What it does not do

Bug reports only. A feature request is a design decision, and design decisions
stay with Shonu. The pipeline classifies the report and stops on anything that is
not a bug.

## Shape

```
contributor files an issue
  → contributor-fix.yml  (allowlist, triage, reproduce, fix, open PR)
    → pr-build.yml       (build mac + win, publish pr-<n> prerelease, post link)
      → contributor installs the real binary, tests on their own hardware
        → contributor comments the approval phrase
          → contributor-merge.yml (allowlist, merge to testing, dispatch build)
            → testing-app.yml     (existing; every alpha tester receives it)
```

The contributor who reported the bug is the person who confirms the fix. They are
the only person with the braille display. That check cannot be automated, so it
is placed at the merge gate rather than left out.

## Files

| File | Trigger | Does |
|---|---|---|
| `.github/contributors.yml` | data | The allowlist. One source of truth for both gates. |
| `.github/ISSUE_TEMPLATE/bug-report.yml` | contributor files an issue | A form: what happened, what was expected, the diagnostics dump |
| `.github/workflows/contributor-fix.yml` | `issues: [opened]` | Allowlist check, triage, fix, open PR |
| `.github/workflows/pr-build.yml` | `pull_request` | Build both platforms, publish `pr-<n>` prerelease, post the link |
| `.github/workflows/contributor-merge.yml` | `issue_comment` on a PR | Allowlist check, merge to `testing`, dispatch `testing-app` |

## Not verified

- Nobody has run the e2e suite in this session. The stale-test finding is from
  reading code, not from a run.
- `docs/nemeth-v2/HANDOFF.md:82` says the suite **hangs** rather than completing
  when run outside a normal logged-in terminal. A GitHub Actions runner is that
  case. Nobody has tried it. Fixing tests does not fix a hang.
- GitHub's issue form has not been checked with a screen reader.

## Phase 0 — make the e2e signal honest

The agent's gate is worthless if the suite is red on a clean tree. It is worse
than worthless if the suite hangs, because the job never ends.

1. Rewrite the 11 `enterCommand` tests against the current composer, across
   `test/e2e/ueb-text-command-mode.test.js`, `test/e2e/unified-composer.test.js`
   and `test/e2e/mathjax-navigation.test.js`. The premise is one obsolete chord,
   so expect one shared fix, not 11.
2. Diagnose the four failures in `test/e2e/app.test.js`. These are unscoped until
   someone runs them.
3. Prove `npm run test:e2e` completes on a `macos-latest` runner. If it hangs,
   fall back to running e2e file by file, which `HANDOFF.md` says works.

Phase 0 ends when `npm run test:e2e` is green and finishes in CI.

Do not delete a failing test to reach green. `CLAUDE.md` already names that as
gaming a gate.

## Phase 1 — intake and fix, Shonu merges

Build `.github/contributors.yml`, `.github/ISSUE_TEMPLATE/bug-report.yml` and
`.github/workflows/contributor-fix.yml`.

The issue form asks three things:

| Field | Why |
|---|---|
| What happened | The report |
| What you expected instead | Separates a bug from a preference |
| Diagnostics | The output of `Help → Copy braille input diagnostics` |

`contributor-fix.yml` runs in this order:

1. Check the issue author against `.github/contributors.yml`. A name that is not
   on the list produces no run at all. Set `allowed_non_write_users` from the
   same list and pass an explicit `github_token`, because contributors have no
   write access and the action would otherwise refuse them.
2. Classify the report. A bug goes on. Anything else gets the label
   `needs-design`, a comment saying why, and stops.
3. Reproduce the bug. Write a failing test first.
4. Fix it. Run the gates below.
5. Open a PR against `testing`.

Gates the agent must pass before it opens the PR:

| Command | Must be |
|---|---|
| `npm test` | 439/439 |
| `npm run nemeth:coverage` | `ERROR` = 0 |
| `npm run nemeth:utility` | 26/26 core |
| `npm run test:e2e` | green, once Phase 0 lands |

Cost controls: `--max-turns` in `claude_args`, a job `timeout-minutes`, and a
`concurrency` group so one issue cannot start several runs.

Phase 1 ends when a contributor's bug becomes a PR without Shonu touching it.
Shonu still presses merge, and watches the first several fixes to judge whether
the agent's reasoning holds up on this codebase.

## Phase 2 — the contributor merges

Build `.github/workflows/pr-build.yml` and
`.github/workflows/contributor-merge.yml`.

`pr-build.yml` publishes each PR build to its own prerelease, tagged `pr-<n>`,
with plainly named mac and Windows assets. It posts one comment with one link per
platform. This mirrors the `testing-app` release page contributors already use.
GitHub Actions artifacts were rejected for this: a run page, an artifacts
section, and a zip inside a zip is a worse path with a screen reader.

`contributor-merge.yml` triggers on `issue_comment`, checks the commenter against
`.github/contributors.yml`, checks for the approval phrase, merges to `testing`,
then dispatches `testing-app.yml`. Without that dispatch the merge ships nothing,
because a `GITHUB_TOKEN` merge fires no `push` workflow.

This workflow must not check out or execute PR head code. It runs from the
default branch with repo secrets, and only calls the merge API.

Phase 2 ends when Shonu is out of the loop.

## Standing notes: disclose, do not veto

`CLAUDE.md` and `docs/nemeth-v2/HANDOFF.md` list things removed on purpose. Six-key
chording. Reusing `src/domain/ueb-cell-buffer.js` for Nemeth. Weakening a Nemeth
gate to move a number.

The agent reads those notes so it knows the traps. It does not treat them as law.

The reason: this repo's own rule is evidence over guesswork, and a blind
contributor's report is evidence. The notes are also evidence, but older, and
often from a different contributor. Neither automatically wins.

So when a fix contradicts a standing note, the PR body must say three things:

1. What it reverses.
2. Why that thing was removed.
3. Why this report outweighs that.

The contributor keeps the last word. The trade stops happening silently.

This is the one hole the contributor cannot close by testing. A contributor asked
to confirm "is the bug gone" will approve a fix that re-adds a removed feature,
because for them it works. Disclosure is what makes that visible to Shonu.

## Decisions

| Decision | Chosen | Rejected, and why |
|---|---|---|
| Channel | GitHub Issues | **Slack** — Claude Code in Slack runs each session under the account of the person who typed it, on their plan limits and their connected repos. Every contributor would need to buy their own Max plan. **Claude Tag**, the shared-identity version, is Team/Enterprise only. |
| Channel | GitHub Issues | **In-app submit button** — the app is offline by design, and shipping a network call plus an embedded credential in an unsigned build breaks that. |
| Channel | GitHub Issues | **Email polled by a job** — no signup for anyone, but it adds an inbox parser to run and secure, and anyone learning the address can drive the repo. |
| Contributor step | Contributors make free GitHub accounts | Forwarding email by hand was offered and turned down; it keeps Shonu in the loop. |
| Stop point | Contributor tests the binary, then merges | Shonu proposed this over both offered options. Better than either: it puts the only un-automatable check, real hardware, at the gate. |
| Standing notes | Disclosure in the PR body | **A second agent with a veto** — rejected. The blind contributor's experience outranks what ended up in `CLAUDE.md`. The notes inform the agent; they do not block it. |
| Test build delivery | Per-PR prerelease | GitHub Actions artifacts — worse to reach with a screen reader. |
| e2e | Fix the failures, then require green | Recording a baseline of known failures was offered and turned down. |
| Build order | Phase 1 before Phase 2 | Building the whole loop at once. Shonu watches the agent's judgement on real bugs before handing a contributor the merge button. |

## Risks accepted

- A merge to `testing` reaches every alpha tester, and Windows installs it in the
  background. Accepted: `testing` is experimental, and everyone running it knows.
- The agent may re-add something removed on purpose. Mitigated by disclosure, not
  prevented.
- The e2e suite may not be runnable in CI at all. Phase 0 finds out. If it is
  not, the fallback is per-file runs.
